# 関連設計書一覧（作成計画）

## システム名：Artリーブ

今後作成する設計書・資料を分類ごとに整理する。個人開発の規模に合わせ、一部は独立した文書を作らず機能定義書の該当セクションで代替する。

| 分類 | 設計書・資料名 | 目的 | 作成方針 |
|---|---|---|---|
| 基本設計 | 基本設計書 | システム全体の構成・方針を定義する | 作成する |
| 基本設計 | 画面設計書 | 各画面のレイアウト・遷移を定義する | 作成する |
| 基本設計 | ユースケース図／シーケンス図 | 利用者の操作フローと処理の流れを明確にする | 作成する |
| 詳細設計 | テーブル設計書 | 各テーブルのカラム・型・制約を定義する | 作成する |
| 詳細設計 | ER図 | テーブル間のリレーションを図示する | 作成する |
| 詳細設計 | API設計書 | エンドポイント・リクエスト／レスポンス仕様を定義する | 作成する |
| 全体・基盤 | 非機能要件定義書／方式設計書 | 性能・セキュリティ・インフラ方針を定義する | 簡略化（機能定義書「非機能要件」「本番環境」で代替し、独立した文書は作らない） |
| 全体・基盤 | インフラ・ネットワーク構成図 | 自宅サーバー・ネットワークの構成を図示する | 作成する（自宅サーバー特有の構成のため優先度高） |
| 詳細仕様 | 状態遷移図（ステートマシン図） | 複雑なステータス変化を明確にする | 必要箇所のみ部分作成（例：公開設定の公開範囲の状態管理） |
| 詳細仕様 | バッチ処理（ジョブ）設計書 | 定期・非同期処理を明確にする | 独立した文書は作らず、運用手順書内に記載する |
| 品質・運用 | テスト計画書／仕様書 | テスト範囲・観点を定義する | 作成する（個人開発規模の簡易版） |
| 品質・運用 | 運用・保守・障害対応手順書 | 運用中のトラブル対応手順を定義する | 作成する |
| 構築・運用 | 環境構築・デプロイ手順書 | Raspberry Pi＋Docker＋Caddy＋DDNSの構築手順を、誰が見ても再現できる形で残す | 作成する（自宅サーバー特有のため優先度高） |
| 構築・運用 | バックアップ・リストア手順書 | バックアップの取得だけでなく、実際に復旧できる手順まで定義する | 作成する（運用・保守手順書に統合する形でも可） |
