## 1. 方針

| 項目 | 内容 |
|---|---|
| 目標 | RPO 24時間（最大で前日3時の状態まで戻せる）、RTO 1日（SSDが壊れても1日以内に復旧） |
| 保管場所 | ①Pi本体のSSD ②外部クラウドストレージ（Google ドライブ、rcloneで暗号化） |
| 確認 | バックアップは「取れている」だけでなく「戻せる」ことを月1回の訓練で確かめる（5章） |

ユーザーの操作ミス（設定を消してしまった等）は、まずアプリ内の変更履歴（F-13）から戻す。本書のDB復元は、アプリが動かない・データ全体が壊れたときの最終手段とする（復元すると、バックアップ以降の変更はすべて失われるため）。

---

## 2. バックアップの対象

| 対象 | 方法 | 頻度 | 保持 | 保管場所 |
|---|---|---|---|---|
| DB（日次） | B-01：pg_dump | 毎日3:00 | 7世代 | SSD＋外部 |
| DB（週次） | B-01：日曜分をコピー | 毎週日曜 | 4世代 | SSD＋外部 |
| DB（デプロイ前） | deploy.sh | デプロイごと | 3世代 | SSDのみ |
| イラスト | B-02：rclone sync | 毎日3:30 | 最新＋削除後30日 | 外部 |
| 秘密情報 | 手動 | 変更したとき | 最新 | パスワード管理アプリ（6章） |
| 証明書（Caddy） | 対象外 | — | — | 失っても自動で再取得される |
| アプリのコード・設定ファイル | 対象外 | — | — | GitHubにある |

## 3. バックアップの確認方法

```bash
# ローカルのDBダンプ
ls -lh /srv/artleave/backups/db/daily/ /srv/artleave/backups/db/weekly/

# 外部ストレージの内容（ファイル名は自動で復号されて表示される）
rclone ls remote-crypt:artleave/db
rclone size remote-crypt:artleave/uploads

# 直近のジョブ結果
tail -n 20 /srv/artleave/logs/batch/B-01_$(date +%Y%m%d).log
```

Healthchecks.ioの管理画面で、B-01・B-02が毎日緑（成功）になっていることも確認できる。

## 4. リストア手順

どの手順を使うかは状況で選ぶ。

| 状況 | 使う手順 |
|---|---|
| 一部のキャラ・設定を誤って変えた／消した | アプリの変更履歴（SC-60、SC-61）から復元。本書は使わない |
| デプロイ後にDBがおかしくなった、DBが壊れた | 4.1 DBのみ復元 |
| 一部のイラストが表示されない（ファイルが消えた） | 4.2 イラストのみ復元 |
| SSDが壊れた、Piが起動しない、Piごと失った | 4.3 全体復旧 |

### 4.1 DBのみ復元

```bash
cd /opt/artleave

# 1. 使うダンプを決める（通常は最新の日次、デプロイ失敗時は predeploy_*）
ls -lt /srv/artleave/backups/db/daily/ /srv/artleave/backups/db/predeploy_* 2>/dev/null
DUMP=/srv/artleave/backups/db/daily/artleave_YYYYMMDD.dump

# 2. 念のため、今の状態もダンプしておく（復元をやり直せるように）
docker compose exec -T db pg_dump -U artleave -Fc artleave \
  > /srv/artleave/backups/db/before_restore_$(date +%Y%m%d_%H%M%S).dump

# 3. アプリを止める（DBへの接続を切るため）
docker compose stop app

# 4. DBを作り直して復元
docker compose exec -T db dropdb   -U artleave artleave
docker compose exec -T db createdb -U artleave artleave
docker compose exec -T db pg_restore -U artleave -d artleave --no-owner < "$DUMP"

# 5. アプリを起動して確認
docker compose start app
curl -fsS https://artleave.example.com/api/v1/health
```

ローカルにダンプがない場合は、先に外部から取り出す：

```bash
rclone copy remote-crypt:artleave/db/daily/artleave_YYYYMMDD.dump /srv/artleave/backups/db/daily/
```

確認：ログインし、図鑑の件数・最近更新したキャラの内容がダンプの日時どおりになっていること。

### 4.2 イラストのみ復元

```bash
# 特定のキャラのイラストだけ戻す（フォルダ構成：uploads/{userId}/{characterId}/）
rclone copy remote-crypt:artleave/uploads/<userId>/<characterId> \
  /srv/artleave/uploads/<userId>/<characterId>

# すべて戻す（既にあるファイルは上書きしない）
rclone copy --ignore-existing remote-crypt:artleave/uploads /srv/artleave/uploads

# 権限をappコンテナの実行ユーザーに合わせる
sudo chown -R 1001:1001 /srv/artleave/uploads
```

消してから30日以内のイラストは`remote-crypt:artleave/uploads-deleted/<日付>/`にも残っている。

### 4.3 全体復旧（SSD故障・Piごと失った場合）

所要時間の目安：機材がそろっていれば3〜4時間（イラストの量による）。

| 手順 | 作業 | 参照 |
|---|---|---|
| 1 | 新しいSSD（必要ならPi本体も）を用意し、OSを書き込む | 13 第2部 2.2 |
| 2 | 初期設定・Docker・Tailscale・ファイアウォール・ディレクトリ作成 | 13 第2部 2.4〜2.8 |
| 3 | リポジトリを取得 | 13 第2部 2.11 |
| 4 | パスワード管理アプリから`.env`・`.env.batch`・rcloneの設定を書き戻す | 本書 6章 |
| 5 | 外部ストレージからDBダンプとイラストを取り出す | 下記 |
| 6 | DBだけ起動して復元 → 全体を起動 | 下記 |
| 7 | バッチ（crontab）を再設定 | 13 第2部 2.15 |
| 8 | 動作確認・監視の再開 | 13 第2部 2.17 |

Piを新しくした場合はMACアドレスが変わるため、ルーターのDHCP予約とTailscale上の端末（古い端末は管理画面で削除）も更新する。

手順5・6の詳細：

```bash
cd /opt/artleave

# rcloneの設定ファイルを書き戻す（パスワード管理アプリに保存した内容）
mkdir -p ~/.config/rclone && nano ~/.config/rclone/rclone.conf
rclone lsd remote-crypt:artleave        # db と uploads が見えればOK

# データの取り出し
rclone copy remote-crypt:artleave/db /srv/artleave/backups/db
rclone copy remote-crypt:artleave/uploads /srv/artleave/uploads --progress
sudo chown -R 1001:1001 /srv/artleave/uploads

# DBだけ起動して空のDBに復元
docker compose up -d db
sleep 10
DUMP=$(ls -1t /srv/artleave/backups/db/daily/*.dump | head -1)
docker compose exec -T db pg_restore -U artleave -d artleave --no-owner < "$DUMP"

# 全体を起動
docker compose up -d --build
curl -fsS https://artleave.example.com/api/v1/health
```

DBとイラストのバックアップ時刻には最大30分の差がある。DBに登録がありファイルがないイラストは表示されないため、該当があれば画面から再アップロードする。逆にファイルだけ残っているものは、週次のB-04が自動で掃除する。

## 5. 月1回のリストア訓練

本番に影響を与えないよう、開発PCで行う。

```bash
# 1. 外部ストレージから最新のダンプを取り出す（開発PCにもrcloneと同じ設定を入れておく）
rclone copy remote-crypt:artleave/db/daily ./restore-test --max-age 2d

# 2. 訓練用のDBを一時的に起動
docker run -d --name artleave-restore-test -e POSTGRES_PASSWORD=test -e POSTGRES_USER=artleave -e POSTGRES_DB=artleave postgres:16
sleep 10

# 3. 復元
docker exec -i artleave-restore-test pg_restore -U artleave -d artleave --no-owner < ./restore-test/artleave_*.dump

# 4. 件数を確認（本番の画面に表示される件数と見比べる）
docker exec -i artleave-restore-test psql -U artleave -d artleave -c \
  "select (select count(*) from characters) chars, (select count(*) from illustrations) imgs, (select max(changed_at) from change_histories) last_change;"

# 5. 片付け
docker rm -f artleave-restore-test && rm -rf ./restore-test
```

訓練記録

| 実施日 | 使ったダンプ | キャラ数 | イラスト数 | 最終変更日時 | 所要時間 | 結果 | 備考 |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

3か月に1回は、イラストの取り出し（`rclone copy`で任意のキャラ1人分）も合わせて確認する。

## 6. 秘密情報の保管

次の情報はPiのSSDの中にしかないため、SSDが壊れると失われる。変更するたびにパスワード管理アプリ（Bitwarden等）に保存する。**特にrcloneの暗号化パスワードを失うと、外部のバックアップを一切復元できなくなる。**

| 項目 | Pi上の場所 |
|---|---|
| 本番の環境変数 | `/opt/artleave/.env` |
| バッチの通知先 | `/opt/artleave/.env.batch` |
| rcloneの設定（Google ドライブの認証情報・暗号化パスワードとソルト） | `~/.config/rclone/rclone.conf` |
| GitHubのデプロイ鍵 | `~/.ssh/github_deploy`（失った場合は作り直して再登録すればよい） |
| Cloudflare APIトークン | `.env`に含まれる（失った場合はCloudflareで再発行できる） |
