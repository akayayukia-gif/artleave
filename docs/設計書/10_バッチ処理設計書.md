## 1. 基本方針

| 項目 | 方針 |
|---|---|
| 実行基盤 | Pi本体のcron（`crontab -e`で`artleave`ユーザーに登録）。専用のジョブ管理ツールは使わない |
| 実行方法 | シェルスクリプト（`/opt/artleave/scripts/`）から`docker compose exec`でコンテナ内の処理を呼ぶ |
| 実行時間帯 | 利用の少ない深夜2:00〜5:00に集中させ、処理同士が重ならないよう時刻をずらす |
| 二重起動防止 | `flock`でロックを取り、前回の実行中なら新しい実行は何もせず終了 |
| ログ | `/srv/artleave/logs/batch/{ジョブID}_{日付}.log`。30日より古いものは削除 |
| 結果通知 | Healthchecks.ioへ開始・成功・失敗をping。予定時刻を過ぎても成功pingがなければメールが届く |
| 終了コード | 0＝成功、1以上＝失敗（スクリプトは`set -euo pipefail`で途中のエラーを見逃さない） |

```
0  5 * * *  /opt/artleave/scripts/run-job.sh B-06 /opt/artleave/scripts/rotate-logs.sh
```

`run-job.sh`は全ジョブ共通の入口で、ロック取得・ログ出力・Healthchecks.ioへの通知をまとめて行う。

```bash
#!/usr/bin/env bash
# run-job.sh <ジョブID> <スクリプト>
set -euo pipefail
JOB_ID="$1"; SCRIPT="$2"
source /opt/artleave/.env.batch          # HC_URL_B01 などのping先
LOG_DIR=/srv/artleave/logs/batch
LOG="$LOG_DIR/${JOB_ID}_$(date +%Y%m%d).log"
HC_VAR="HC_URL_${JOB_ID//-/}"; HC_URL="${!HC_VAR}"

mkdir -p "$LOG_DIR"
exec 9>"/tmp/artleave_${JOB_ID}.lock"
flock -n 9 || { echo "$(date -Is) skip: already running" >> "$LOG"; exit 0; }

curl -fsS -m 10 "$HC_URL/start" > /dev/null || true
if "$SCRIPT" >> "$LOG" 2>&1; then
  curl -fsS -m 10 "$HC_URL" > /dev/null || true
else
  code=$?
  curl -fsS -m 10 "$HC_URL/fail" > /dev/null || true
  exit $code
fi
```

## 3. ジョブ詳細

### B-01 DBバックアップ

| 項目 | 内容 |
|---|---|
| 目的 | DBの内容を毎日ファイルに保存する（RPO 24時間） |
| 入力 | PostgreSQLコンテナ（artleave DB） |
| 出力 | `/srv/artleave/backups/db/daily/artleave_YYYYMMDD.dump` |
| 処理 | 1. `pg_dump -Fc`でカスタム形式のダンプを作成<br>2. `pg_restore --list`で読み込めることを確認（壊れたダンプを残さない）<br>3. 日曜日は`weekly/`にもコピー<br>4. 世代管理：daily は7世代、weekly は4世代を残して古いものを削除 |
| 失敗時 | ダンプ途中のファイルは削除して異常終了（前日までのダンプは残る） |

```bash
#!/usr/bin/env bash
set -euo pipefail
cd /opt/artleave
BK=/srv/artleave/backups/db
DATE=$(date +%Y%m%d)
TMP="$BK/daily/.artleave_${DATE}.dump.tmp"
OUT="$BK/daily/artleave_${DATE}.dump"
mkdir -p "$BK/daily" "$BK/weekly"

trap 'rm -f "$TMP"' ERR
docker compose exec -T db pg_dump -U artleave -Fc artleave > "$TMP"
docker compose exec -T db pg_restore --list < "$TMP" > /dev/null
mv "$TMP" "$OUT"

[ "$(date +%u)" = "7" ] && cp "$OUT" "$BK/weekly/"
ls -1t "$BK"/daily/*.dump  | tail -n +8 | xargs -r rm -f
ls -1t "$BK"/weekly/*.dump | tail -n +5 | xargs -r rm -f
echo "$(date -Is) backup ok: $OUT ($(du -h "$OUT" | cut -f1))"
```

### B-02 外部ストレージへの退避

| 項目 | 内容 |
|---|---|
| 目的 | SSD故障・盗難・火災などで本体ごと失っても復旧できるようにする |
| 退避先 | Google ドライブ（無料15GB）。rcloneの暗号化機能（crypt）を通し、中身もファイル名も暗号化して保存 |
| 対象 | `backups/db/`（DBダンプ）と`uploads/`（イラスト） |
| 処理 | 1. `rclone sync backups/db  remote-crypt:artleave/db`<br>2. `rclone sync uploads remote-crypt:artleave/uploads --backup-dir remote-crypt:artleave/uploads-deleted/<日付>`（消したイラストも30日間は外部に残す）<br>3. 30日を過ぎた`uploads-deleted`を削除 |
| 前提 | B-01が成功していること（B-01の成功ログがなければ警告を出して画像のみ同期） |
| 失敗時 | ネットワーク等の一時的なエラーはrcloneが自動で再試行（3回）。それでも失敗した場合は異常終了し、翌日の実行で差分を同期 |
| 注意 | rcloneの暗号化パスワードはPi以外（パスワード管理アプリ等）にも必ず保管する。失うと外部のバックアップを復元できない |

### B-03 期限切れトークンの削除

| 項目 | 内容 |
|---|---|
| 目的 | 不要になったパスワード再設定トークンを残さない |
| 処理 | `DELETE FROM password_reset_tokens WHERE used_at IS NOT NULL OR expires_at < now() - interval '1 day';` |
| 失敗時 | 異常終了。翌日の実行で再度削除される（データの整合性には影響しない） |

### B-04 孤立した画像ファイルの掃除

| 項目 | 内容 |
|---|---|
| 目的 | アップロード失敗等でDBに登録されずに残った画像ファイルを削除し、容量を確保する |
| 処理 | 1. `uploads/`配下のイラストIDフォルダ一覧を取得<br>2. `illustrations`テーブルに存在しないIDを抽出<br>3. 作成から24時間以上経過したものだけを削除（アップロード処理中のファイルを消さないため）<br>4. 削除件数と容量をログに出力 |
| 実行方法 | アプリのコードとして実装し、`docker compose exec -T app`から呼ぶ（DBとストレージの両方を見る必要があるため）。画像管理機能（F-09）と合わせて実装する |
| 安全策 | 1回で全体の10%を超える数が対象になった場合は、異常とみなして何も削除せず失敗終了する |

### B-05 ディスク使用率チェック

| 項目 | 内容 |
|---|---|
| 目的 | 容量不足でDBや画像の保存が失敗する前に気づく |
| 処理 | `/srv/artleave`のあるディスクの使用率を確認し、80%以上なら失敗終了（＝メール通知） |
| 通知を受けたら | 12_運用・保守・障害対応手順書「障害4：ディスク容量不足」に従う |

### B-06 古いログの削除

| 項目 | 内容 |
|---|---|
| 目的 | バッチのログが溜まり続けるのを防ぐ |
| 処理 | `find /srv/artleave/logs/batch -name '*.log' -mtime +30 -delete` |
| 備考 | コンテナのログはDockerの設定（10MB×3世代）、Caddyのアクセスログはroll設定で自動的に古いものが消える |
