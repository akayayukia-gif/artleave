## 第1部 開発環境の構築（開発PC）

### 1.1 必要なソフトウェア

| ソフトウェア | 用途 | 入手先 |
|---|---|---|
| Git | バージョン管理 | git-scm.com |
| Docker Desktop | 開発用DB | docker.com |
| Volta | Node.js・pnpmのバージョン固定 | volta.sh |
| VS Code | エディタ | code.visualstudio.com |

VS Codeの拡張機能：Biome、Prisma、Tailwind CSS IntelliSense

### 1.2 手順

```bash
# 1. Node.js と pnpm を入れる（package.json の volta 設定と同じバージョンになる）
volta install node@22 pnpm

# 2. リポジトリを取得して依存関係を入れる
git clone git@github.com:<GitHubユーザー名>/artleave.git
cd artleave
pnpm install

# 3. 環境変数ファイルを作る（値は下表を参照）
cp .env.example .env.local

# 4. 開発用DBを起動
docker compose -f docker-compose.dev.yml up -d

# 5. テーブル作成と開発用データの投入
pnpm prisma migrate dev
pnpm prisma db seed

# 6. 開発サーバー起動 → http://localhost:3000
pnpm dev
```

`.env.local`の値（開発用）

| 変数 | 値の例 |
|---|---|
| DATABASE_URL | `postgresql://artleave:artleave@localhost:5432/artleave` |
| AUTH_SECRET | `openssl rand -base64 32`で生成した値 |
| AUTH_URL | `http://localhost:3000` |
| UPLOAD_DIR | `./.uploads` |
| SMTP_HOST／SMTP_USER／SMTP_PASS | 空でよい（開発中はメール本文をコンソールに出力する） |

`docker-compose.dev.yml`

```yaml
services:
  db:
    image: postgres:16
    ports:
      - "5432:5432"
    environment:
      POSTGRES_DB: artleave
      POSTGRES_USER: artleave
      POSTGRES_PASSWORD: artleave
    volumes:
      - artleave-dev-db:/var/lib/postgresql/data
volumes:
  artleave-dev-db:
```

### 1.3 よく使うコマンド

| コマンド | 内容 |
|---|---|
| `pnpm dev` | 開発サーバー |
| `pnpm check` | Biomeで静的解析と整形チェック（`pnpm check --write`で自動修正） |
| `pnpm typecheck` | 型チェック（`tsc --noEmit`） |
| `pnpm test` | Vitestで単体・結合テスト |
| `pnpm prisma studio` | DBの中身をGUIで確認 |
| `pnpm prisma migrate dev --name <名前>` | テーブル変更のマイグレーション作成 |
| `docker compose -f docker-compose.dev.yml down -v` | 開発DBを完全に作り直したいとき（データは消える） |

### 1.4 ブランチ運用

1. `main`から`feature/<機能ID>-<内容>`（例：`feature/F-07-relationship-map`）を作る
2. 作業してpushし、プルリクエストを作る
3. CI（Lint・型チェック・テスト・ビルド）が通ったら`main`にマージ
4. マージすると自動で本番にデプロイされる（第3部）

## 第2部 本番環境の構築（Raspberry Pi）

### 2.1 準備するもの

08_インフラ・ネットワーク構成図「2. ハードウェア構成」の機器一式、独自ドメイン、Cloudflareアカウント、Tailscaleアカウント、UptimeRobotアカウント、Healthchecks.ioアカウント（いずれも無料）。

### 2.2 OSをSSDに書き込む

1. 開発PCに「Raspberry Pi Imager」を入れ、SSDをUSBでつなぐ
2. デバイス：Raspberry Pi 5、OS：Ubuntu Server 24.04 LTS（64-bit）、書き込み先：SSD
3. 「設定を編集する」で次を設定
   - ホスト名：`artleave`
   - ユーザー名：`artleave`
   - SSH：有効、「公開鍵認証のみ」にして開発PCの公開鍵（`~/.ssh/id_ed25519.pub`）を貼る
   - タイムゾーン：Asia/Tokyo
4. 書き込んだSSDをPiにつなぎ、LANケーブルと電源をつないで起動（microSDカードは挿さない。Pi 5はSDがなければUSBから起動する）

### 2.3 固定IPの設定

ルーターの管理画面で、PiのMACアドレスに`192.168.1.50`を割り当てる（DHCP予約）。設定後にPiを再起動。

### 2.4 初期設定

```bash
ssh artleave@192.168.1.50

# OSを最新に
sudo apt update && sudo apt full-upgrade -y

# セキュリティ更新だけ自動で入れる
sudo apt install -y unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades

# SSHのパスワードログインとrootログインを禁止
sudo tee /etc/ssh/sshd_config.d/10-hardening.conf <<'EOF'
PasswordAuthentication no
PermitRootLogin no
EOF
sudo systemctl restart ssh
```

### 2.5 Dockerのインストール

```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker artleave
sudo systemctl enable docker      # 起動時に自動でDockerが立ち上がる（停電復帰のため）
exit                              # 入り直してdockerグループを反映
```

### 2.6 Tailscale（SSHを外に開けないため）

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up
# 表示されたURLをブラウザで開いてログイン → 管理画面でこの端末の「Key expiry」を無効化
tailscale ip -4    # 100.x.x.x のアドレスを控える
```

開発PCにもTailscaleを入れて同じアカウントでログインすれば、自宅の外からも`ssh artleave@artleave`で接続できる。

### 2.7 ファイアウォール

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow in on tailscale0 to any port 22 proto tcp
sudo ufw allow from 192.168.1.0/24 to any port 22 proto tcp   # 自宅LANからの保守用
sudo ufw enable
```

### 2.8 データ用ディレクトリ

```bash
sudo mkdir -p /srv/artleave/{pgdata,uploads,caddy/data,caddy/config,backups/db/daily,backups/db/weekly,logs/batch}
sudo chown -R artleave:artleave /srv/artleave
sudo chown 1001:1001 /srv/artleave/uploads   # appコンテナの実行ユーザー（UID 1001）が書き込めるように
sudo mkdir -p /opt/artleave && sudo chown artleave:artleave /opt/artleave
```

### 2.9 ドメインとDDNS

1. ドメインのネームサーバーをCloudflareに変更
2. CloudflareのDNSに`artleave.example.com`のAレコードを作成（値は仮で`1.1.1.1`、プロキシは「DNSのみ」）。実際のIPはddnsコンテナが自動で書き換える
3. Cloudflareの「APIトークン」で「Zone.DNS 編集」権限、対象ゾーンを自分のドメインに限定したトークンを作成し、控える

### 2.10 ルーターのポート転送

| 外部ポート | 転送先 |
|---|---|
| TCP 80 | 192.168.1.50:80 |
| TCP 443 | 192.168.1.50:443 |

UPnPは無効にする。

### 2.11 リポジトリの取得

```bash
# Pi用のデプロイ鍵を作り、GitHubリポジトリの Settings > Deploy keys に「読み取り専用」で登録
ssh-keygen -t ed25519 -f ~/.ssh/github_deploy -N ""
cat ~/.ssh/github_deploy.pub

cat >> ~/.ssh/config <<'EOF'
Host github.com
  IdentityFile ~/.ssh/github_deploy
EOF

git clone git@github.com:<GitHubユーザー名>/artleave.git /opt/artleave
```

### 2.12 本番用の環境変数

```bash
cd /opt/artleave
cp .env.example .env
chmod 600 .env
nano .env
```

| 変数 | 値 |
|---|---|
| POSTGRES_PASSWORD | `openssl rand -base64 24`で生成 |
| DATABASE_URL | `postgresql://artleave:<POSTGRES_PASSWORD>@db:5432/artleave` |
| AUTH_SECRET | `openssl rand -base64 32`で生成（開発用とは別の値） |
| AUTH_URL | `https://artleave.example.com` |
| SMTP_HOST／SMTP_USER／SMTP_PASS | `smtp.gmail.com`／Gmailアドレス／Googleアカウントで発行したアプリパスワード |
| CLOUDFLARE_API_TOKEN | 2.9で作成したトークン |
| DOMAIN | 公開するドメイン（例：`artleave.example.com`）。CaddyとDDNSが使う |

### 2.13 初回起動

```bash
cd /opt/artleave
docker compose up -d --build     # 初回は10〜15分程度かかる
docker compose ps                # 4つのコンテナがrunning（dbはhealthy）であること
docker compose logs -f app       # 「prisma migrate deploy」完了 → 「Ready」を確認
```

- テーブル作成（マイグレーション）は`migrate`サービスが`prisma migrate deploy`を実行してから終了し、その後に`app`が起動する（`docker compose ps -a`で`migrate`が`Exited (0)`なら成功）。ポーズマスタの初期データもマイグレーションに含まれる。
- Caddyが初回アクセス時にLet's Encryptの証明書を取得する。

確認：

```bash
curl -I https://artleave.example.com              # HTTP/2 200 または 307（ログインへ転送）
curl https://artleave.example.com/api/v1/health   # {"status":"ok"}
```

スマートフォンのモバイル回線（Wi-Fiを切った状態）からもアクセスできることを確認する。

### 2.14 Dockerfile

リポジトリの`Dockerfile`を使う。3段階（deps → build → runner）でビルドし、実行用イメージには`next build`の`standalone`出力だけを入れる。

- `next.config.ts`で`output: "standalone"`を設定している。
- DBのマイグレーションは実行用イメージではなく、`docker-compose.yml`の`migrate`サービスが`build`ステージ（Prisma CLIを含む）を使って行う。
- Pi上で直接ビルドするため、`@node-rs/argon2`などのARM64向けバイナリが自動で選ばれる。

### 2.15 バッチの設定

```bash
# rclone（外部ストレージ）
sudo apt install -y rclone
rclone config
#  1) n → 名前「gdrive」→ Google Drive を選択 → ブラウザ認証（Pi上にブラウザがないため「remote config」の案内に従い開発PCで認証）
#  2) n → 名前「remote-crypt」→ crypt を選択 → remote に「gdrive:artleave-backup」
#     → ファイル名も暗号化 → パスワードとソルトを自動生成させ、必ずパスワード管理アプリに保存

# Healthchecks.io でジョブ B-01〜B-06 のチェックを作り、ping URL を記入
cp .env.batch.example .env.batch
chmod 600 .env.batch
nano .env.batch        # HC_URL_B01=https://hc-ping.com/xxxx … を記入

chmod +x scripts/*.sh
crontab -e             # scripts/crontab.example の内容を貼り付け

# 動作確認
scripts/run-job.sh B-01 scripts/backup-db.sh && ls -lh /srv/artleave/backups/db/daily/
scripts/run-job.sh B-02 scripts/sync-offsite.sh && rclone ls remote-crypt:artleave/db
```

### 2.16 外部監視の設定

UptimeRobotで次の2つのモニターを作成する。

| 種類 | 対象 | 間隔 |
|---|---|---|
| HTTP(s) | `https://artleave.example.com/api/v1/health` | 5分 |
| SSL証明書 | `artleave.example.com` | 期限14日前に通知 |

### 2.17 構築後の確認

| 確認内容 | 方法 |
|---|---|
| 外部からのアクセス | モバイル回線からサイトを開く |
| 開いているポート | 外部のポートチェックサービスで80／443以外が閉じていること |
| 停電復帰 | 電源を抜き差しし、3分以内に`/api/v1/health`が200に戻ること |
| 監視 | `docker compose stop app`で5分以内に通知が来ること（確認後`start`） |

## 第3部 CI/CD（自動テスト・自動デプロイ）

### 3.1 CI：`.github/workflows/ci.yml`

```yaml
name: CI
on:
  pull_request:
  push:
    branches: [main]

jobs:
  check:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_DB: artleave_test
          POSTGRES_USER: artleave
          POSTGRES_PASSWORD: artleave
        ports: ["5432:5432"]
        options: >-
          --health-cmd "pg_isready -U artleave"
          --health-interval 5s --health-retries 10
    env:
      DATABASE_URL: postgresql://artleave:artleave@localhost:5432/artleave_test
      AUTH_SECRET: ci-only-secret-not-used-in-production
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm
      - run: pnpm install --frozen-lockfile
      - run: pnpm check
      - run: pnpm typecheck
      - run: pnpm prisma migrate deploy
      - run: pnpm test --coverage
      - run: pnpm build
```

### 3.2 自動デプロイ：`.github/workflows/deploy.yml`

```yaml
name: Deploy
on:
  workflow_run:
    workflows: [CI]
    types: [completed]
    branches: [main]
  workflow_dispatch:          # 手動実行も可能にする

concurrency: deploy           # デプロイを同時に2つ走らせない

jobs:
  deploy:
    if: ${{ github.event_name == 'workflow_dispatch' || github.event.workflow_run.conclusion == 'success' }}
    runs-on: ubuntu-latest
    steps:
      - name: Tailscaleに一時参加
        uses: tailscale/github-action@v3
        with:
          oauth-client-id: ${{ secrets.TS_OAUTH_CLIENT_ID }}
          oauth-secret: ${{ secrets.TS_OAUTH_SECRET }}
          tags: tag:ci

      - name: SSH鍵の準備
        run: |
          mkdir -p ~/.ssh
          echo "${{ secrets.DEPLOY_SSH_KEY }}" > ~/.ssh/id_ed25519
          chmod 600 ~/.ssh/id_ed25519
          echo "${{ secrets.DEPLOY_KNOWN_HOSTS }}" > ~/.ssh/known_hosts

      - name: Piでデプロイスクリプトを実行
        run: ssh artleave@${{ secrets.DEPLOY_HOST }} "/opt/artleave/scripts/deploy.sh"
```

GitHubリポジトリのSecretsに登録する値

| 名前 | 内容 |
|---|---|
| TS_OAUTH_CLIENT_ID／TS_OAUTH_SECRET | Tailscale管理画面で作成したOAuthクライアント（`tag:ci`のみ付与可能にする） |
| DEPLOY_SSH_KEY | デプロイ専用に作った秘密鍵（公開鍵はPiの`~/.ssh/authorized_keys`に登録） |
| DEPLOY_KNOWN_HOSTS | `ssh-keyscan artleave`の結果（なりすまし防止） |
| DEPLOY_HOST | Tailscale上のPiのホスト名（`artleave`）またはIP（100.x.x.x） |

TailscaleのACLで、`tag:ci`からはPiの22番ポートにしか接続できないようにする。

### 3.3 Pi側のデプロイスクリプト：`scripts/deploy.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail
cd /opt/artleave
LOG=/srv/artleave/logs/batch/deploy_$(date +%Y%m%d_%H%M%S).log
exec > >(tee -a "$LOG") 2>&1

PREV=$(git rev-parse HEAD)
echo "== 現在のバージョン: $PREV"

# 1. 念のためデプロイ前にDBをバックアップ（マイグレーション失敗に備える）
docker compose exec -T db pg_dump -U artleave -Fc artleave \
  > "/srv/artleave/backups/db/predeploy_$(date +%Y%m%d_%H%M%S).dump"
ls -1t /srv/artleave/backups/db/predeploy_*.dump | tail -n +4 | xargs -r rm -f   # 3世代だけ残す

# 2. 最新のコードを取得
git fetch origin main
git reset --hard origin/main
echo "== 新しいバージョン: $(git rev-parse HEAD)"

# 3. ビルドして入れ替え（起動時にマイグレーションも実行される）
docker compose up -d --build

# 4. 起動確認（最大3分待つ）
for i in $(seq 1 36); do
  if curl -fsS --resolve artleave.example.com:443:127.0.0.1 \
       https://artleave.example.com/api/v1/health > /dev/null; then
    echo "== デプロイ成功"
    docker image prune -f
    exit 0
  fi
  sleep 5
done

echo "== 起動確認に失敗。前のバージョン ($PREV) に戻します"
git reset --hard "$PREV"
docker compose up -d --build
exit 1
```

### 3.4 手動での切り戻し

自動の切り戻しでは戻らない場合（DBのマイグレーションが途中まで進んでしまった等）：

```bash
cd /opt/artleave
git log --oneline -5                      # 戻したいバージョンを確認
git reset --hard <戻したいコミット>
# マイグレーションでテーブルが変わってしまった場合は、デプロイ前のダンプからDBを戻す
#   → 14_バックアップ・リストア手順書「3.1 DBのみ復元」で predeploy_*.dump を指定
docker compose up -d --build
```

## 付録：自宅のIPアドレスを隠したい場合（Cloudflareプロキシ方式）

初期構成（DNSのみ）では、ドメインから自宅のグローバルIPが分かる。気になる場合は次の方式に切り替える。

1. Cloudflareの「SSL/TLS」→「オリジンサーバー」で証明書を作成し、証明書と秘密鍵を`/srv/artleave/caddy/data/origin/`に保存（コンテナ内では`/data/origin/`）
2. Caddyfileのサイト設定に`tls /data/origin/cert.pem /data/origin/key.pem`を追加（Let's Encryptを使わなくなる）
3. Cloudflareの「SSL/TLS」の暗号化モードを「フル（厳密）」に設定
4. DNSレコードをプロキシ有効（オレンジ雲）にし、ddnsコンテナの`PROXIED`を`"true"`に変更
5. ルーター・ufwで、80／443への接続をCloudflareのIPアドレス範囲からのみに制限すると、さらに安全になる

注意：Cloudflare経由では1回のアップロードが100MBまでに制限される（無料プラン）。イラストの一括アップロードは5枚ずつに分けて送る。
